Use Case Note
■ Workflow
    • El usuario introduce sus credenciales.
    • El sistema verifica la cuenta.
    • Identifica el rol.
    • Permite el acceso correspondiente.
    •
■ Business Logic
    • El sistema debe identificar si el usuario está registrado y autorizado.
    • El sistema debe diferenciar entre cliente y administrador.
    •
■ Decisions
    • ¿El usuario está registrado?
    • ¿Las credenciales corresponden a una cuenta autorizada?
    • ¿El usuario es cliente o administrador?
    •
■ Follow-up
    • El cliente puede acceder a las funcionalidades de cliente.
    • El administrador puede acceder a las funcionalidades administrativas.
    •

Scenario 1 — Inicio de sesión exitoso
Steps
1. El usuario selecciona la opción "Iniciar sesión".
2. El sistema muestra el formulario de inicio de sesión.
3. El usuario ingresa su correo electrónico.
4. El usuario ingresa su contraseña.
5. El usuario selecciona el botón "Iniciar sesión".
6. El sistema verifica las credenciales ingresadas.
7. El sistema identifica al usuario.
8. El sistema verifica que el usuario esté registrado y autorizado.
9. El sistema identifica el rol asociado al usuario.
10. El sistema permite el acceso según el rol identificado.

Scenario 2 — Credenciales incorrectas
Steps
1. El usuario selecciona la opción "Iniciar sesión".
2. El sistema muestra el formulario de inicio de sesión.
3. El usuario ingresa su correo electrónico.
4. El usuario ingresa su contraseña.
5. El usuario selecciona el botón "Iniciar sesión".
6. El sistema valida las credenciales ingresadas.
7. El sistema determina que las credenciales no son válidas.
8. El sistema informa al usuario que las credenciales ingresadas son incorrectas.
9. El sistema mantiene al usuario en el formulario de inicio de sesión.

Scenario 3 — Usuario no registrado o no autorizado
Steps
1. El usuario selecciona la opción "Iniciar sesión".
2. El sistema muestra el formulario de inicio de sesión.
3. El usuario ingresa su correo electrónico.
4. El usuario ingresa su contraseña.
5. El usuario selecciona el botón "Iniciar sesión".
6. El sistema valida las credenciales ingresadas.
7. El sistema identifica la cuenta asociada a las credenciales.
8. El sistema verifica si el usuario está registrado y autorizado.
9. El sistema determina que el usuario no está registrado o no está autorizado.
10. El sistema informa al usuario que no puede acceder al sistema.
11. El sistema mantiene al usuario en el formulario de inicio de sesión.

Scenario 4 — Acceso según rol
Steps
1. El usuario selecciona la opción "Iniciar sesión".
2. El sistema muestra el formulario de inicio de sesión.
3. El usuario ingresa su correo electrónico.
4. El usuario ingresa su contraseña.
5. El usuario selecciona el botón "Iniciar sesión".
6. El sistema valida las credenciales ingresadas.
7. El sistema identifica al usuario.
8. El sistema verifica que el usuario esté registrado y autorizado.
9. El sistema identifica el rol asociado al usuario.
10. El sistema determina que el usuario tiene rol de cliente o administrador.
11. El sistema permite el acceso a las funcionalidades correspondientes al rol identificado.
