Use Case Note
■ Workflow
    • Cliente prepara el carrito.
    • Sistema calcula el total.
    • Cliente confirma.
    • Sistema registra el pedido.
    •
■ Business Logic
    • Solo un cliente que haya iniciado sesión puede realizar el pedido.
    • El pedido debe registrar los productos seleccionados.
    • El pedido debe almacenarse en el sistema.
    •
■ Decisions
    • ¿El cliente ha iniciado sesión?
    • ¿El carrito contiene productos?
    • ¿El cliente confirma el pedido?
    •
■ Follow-up
    • El cliente puede consultar el pedido en su historial.
    • El administrador puede gestionar el pedido.
    •

Scenario
Steps
1. El cliente inicia sesión.
2. El sistema verifica que el cliente esté registrado y autorizado.
3. El cliente selecciona la opción “Realizar pedido”.
4. El sistema verifica que el carrito contenga productos.
5. El sistema muestra el resumen del carrito y el total de la compra.
6. El cliente verifica los productos, cantidades y valor total.
7. El cliente selecciona o registra una dirección de envío.
8. El sistema valida la información de la dirección.
9. El cliente selecciona el método de pago.
10. El sistema muestra las opciones de pago disponibles.
11. El cliente confirma el pedido.
12. El sistema verifica nuevamente la disponibilidad de los productos.
13. El sistema calcula el valor total del pedido.
14. El sistema procesa el pago mediante la pasarela de pago.
15. La pasarela de pago confirma la transacción.
16. El sistema registra el pedido.
17. El sistema actualiza el inventario de los productos vendidos.
18. El sistema genera la factura correspondiente.
19. El sistema envía una confirmación del pedido al cliente.
20. El sistema muestra al cliente la confirmación del pedido y su número de pedido.
21. El sistema establece el estado inicial del pedido como “Confirmado”.
